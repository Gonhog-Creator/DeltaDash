# 1.2.0 - Ballistic Limit ML Plan

## Current State

### How BL Data Is Stored

Ballistic limit (BL) test sessions are flagged via `TestSession.ballistic_limit = true`. This flag is set during Excel parsing when "lim ballistico" or "limite balistico" is detected in the conditioning cell. BL sessions are grouped as children of a parent test session, same as certification sessions.

### How BL Data Is Currently Used in ML

**It's not.** The `ballistic_limit` field is completely absent from the ML pipeline:

- `data_fetcher.py` fetches all `ShotData` regardless of `ballistic_limit` but does not include the flag in training rows
- `ballistic_ml.py` has no `ballistic_limit` feature or target
- Current models: `backface_deformation_mm` (regression), `perforated` and `pass_fail` (classification)

### Data Availability (as of v1.1.2)

| Metric | Non-BL Sessions | BL Sessions |
|--------|----------------|-------------|
| Sessions | 245 | 16 |
| Shots | 2,268 | 192 |
| Shots with velocity | 2,000 | 98 |
| Shots with BFD | 1,763 | 0 |
| Shots with perforation label | 0 | 14 |
| Unique vests | 38 | 6 |
| Unique calibers | 10 | 3 (.357 MAG, .44 MAG, 9mm) |
| Velocity range | 355-1116 m/s | 393-534 m/s |

### What Happens to BL Shots Today

- **BFD regression**: BL shots are naturally excluded - they have `backface_deformation_mm = NaN`, so `dropna(subset=[target])` drops them during training. No issue.
- **Perforation classifier**: 14 BL shots with perforation labels (12 "OK" = not perforated, 1 "PERFORO" = perforated, 1 unlabeled) are included in training without any flag. The model treats them identically to certification shots.
- **84 BL shots with velocity but no labels** are silently dropped by `dropna(subset=all_targets, how="all")` since they have no BFD, no perforation, and no pass_fail.
- **`ballistic_limit` is not passed as a feature** - the model cannot distinguish BL context from certification context.

## Assessment

### Should BL Shots Be Excluded Because They Have No BFD?

No. Exclusion is already handled naturally for BFD regression (NaN values). For the perforation classifier, BL shots are actually the most valuable data available because they explore the failure boundary (velocities near the limit). Certification shots mostly pass, so they teach what "not perforated" looks like but rarely show what "perforated" looks like.

### Is There Enough Data for a Dedicated BL Model?

No. A ballistic limit (V50/V0) model would need to predict the velocity at which a vest fails - essentially a survival analysis problem requiring perforation/no-perforation outcomes across a range of velocities. With 14 perforation labels across 6 vests and 3 calibers, this is far too sparse.

## Plan for v1.2.0

### Phase 1: Add `ballistic_limit` as a Feature

**Goal**: Let the model distinguish BL shots from certification shots.

Changes in `data_fetcher.py`:
- Add `ballistic_limit` to the row dict (from `TestSession.ballistic_limit`)
- Default to `False` for anchor points

Changes in `ballistic_ml.py`:
- Add `ballistic_limit` to `add_engineered_features` as a binary feature
- Add to `numeric_candidates` list
- Add to `prepare_single_input` defaults

Changes in `prediction_service.py`:
- Pass `ballistic_limit` through prediction pipeline (default `False` for predictions)

### Phase 2: Keep BL Shots in Perforation Classifier

No additional filtering needed. The 14 perforation-labeled BL shots are valuable for the classifier. Adding the `ballistic_limit` feature lets the model account for the different context (velocity near threshold, no BFD measurement) rather than conflating it with vest/ammunition characteristics.

### Phase 3: Investigate Unlabeled BL Shots

84 BL shots have velocity but no perforation label and no BFD. If we can infer perforation from velocity patterns (e.g., shots at very high velocity that weren't labeled likely perforated), we could label them. This is speculative without raw data and should be investigated manually before any automated labeling.

### Phase 4: Data Collection

The biggest blocker for a dedicated BL model is data volume. Targets:
- 50+ BL sessions with perforation outcomes
- 10+ unique vests
- 5+ calibers
- Velocity range spanning 300-700+ m/s

### Future: Dedicated V50 Model (v2.0+)

Once sufficient data is collected:
- Logistic regression / survival analysis model predicting P(perforation | velocity, vest, ammo)
- V50 estimation: velocity at which P(perforation) = 0.5
- V0 estimation: velocity at which P(perforation) = 0 (zero penetration)
- Confidence intervals on estimates
- Per-vest, per-caliber BL curves

## Risk: Bias Toward BL Regime

BL shots have velocities in a narrow range (393-534 m/s) across only 3 calibers and 6 vests. Including them in the perforation classifier without the `ballistic_limit` feature could bias the model toward that regime. Adding the feature mitigates this by letting the model learn the context difference.
